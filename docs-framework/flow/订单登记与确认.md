# 场景：订单登记与确认

## 1. 触发入口

- 页面：`/orders/new` 的 [提交订单]、`/orders/:id` 的 [确认订单] / [取消订单]
- 角色：登记＝客户经理；确认＝业务负责人；取消＝客户经理或负责人
- 前置：登记需已选客户且至少 1 项物料；确认需订单处于 `PENDING_CONFIRM`

## 2. 接口链路

1. `POST /api/orders` —— 登记（一次提交订单 + N 项物料）
2. `PUT /api/orders/{id}/confirm` —— 确认
3. `PUT /api/orders/{id}/cancel` —— 取消

## 3. 数据变更（每步一个事务）

登记：

1. 校验客户存在、`tasks` 非空
2. 生成 `order_no`（`AO+yyyyMMdd+4位`，唯一索引兜底，冲突重试）
3. `INSERT material_order(status='PENDING_CONFIRM')`
4. 循环 `INSERT material_task(status='PENDING')`
5. `INSERT operation_log(ORDER_CREATED, detail='含 N 项物料')`

确认：

1. 读订单，校验 `status = PENDING_CONFIRM`，否则 409
2. 校验订单至少 1 项物料
3. `UPDATE material_order SET status='IN_PROGRESS'`
4. `INSERT operation_log(ORDER_CONFIRMED, detail='确认物料清单与整体截止日期 …')`

取消：

1. 读订单，校验 `status = PENDING_CONFIRM`，否则 409
2. `UPDATE material_order SET status='CANCELLED'`
3. `INSERT operation_log(ORDER_CANCELLED)`

## 4. 页面反馈

| 结果 | 反馈 |
|---|---|
| 登记成功 | 跳转订单详情，顶部提示"登记成功"，时间线出现"创建订单" |
| 确认成功 | 状态标签变"进行中"，按钮区切换为负责人视图 |
| 取消成功 | 状态标签变"已取消"，所有操作按钮消失 |
| 409 | 顶部红色消息显示后端 message，随后刷新详情 |
| 400 | 表单校验提示定位到具体字段 |

## 5. 异常与边界

| 场景 | 预期 | 处理 |
|---|---|---|
| 提交空物料列表 | 400 | 前端拦截 + 后端二次校验 |
| 客户已被删除 | 400 | `customerService.requireExists` 抛业务异常 |
| 重复点确认 | 第二次 409 | 状态校验 |
| 设计人员点确认 | 403 | 注解拦截 |
| 取消已进行中的订单 | 409 | 只允许 `PENDING_CONFIRM` |
| 并发取号撞号 | 自动重试 | 唯一索引冲突 → 重试最多 3 次 → 仍失败返回 500 |
