# 场景：任务分派与设计交付

## 1. 触发入口

- 页面：`/orders/:id` 任务行的 [分派]（负责人）、`/my-tasks` 与 `/tasks/:id` 的 [开始设计]、[上传版本]（设计人员本人）
- 前置：分派要求任务 `PENDING`；开始设计要求任务 `PENDING` 且 `assignee_id = 当前用户`；上传要求任务 `DESIGNING` 或 `REVISION`

## 2. 接口链路

1. `PUT /api/tasks/{id}/assign` —— 分派/改派
2. `PUT /api/tasks/{id}/start` —— 开始设计
3. `POST /api/tasks/{id}/versions` —— 上传版本（multipart）
4. `GET /api/files/{path}` —— 下载/预览

## 3. 数据变更

分派：

1. 读任务，校验 `status = PENDING`，否则 409
2. 校验被分派人存在、角色为 `DESIGNER`、`status = 1`，否则 400
3. `UPDATE material_task SET assignee_id=?, assigned_at=NOW()`
4. `INSERT operation_log(TASK_ASSIGNED, detail='【物料名】分派给 姓名')`

开始设计：

1. 读任务，**先校验归属**（`assignee_id = 当前用户`，否则 403）
2. 校验 `status = PENDING`，否则 409
3. `UPDATE material_task SET status='DESIGNING'`
4. 写 `TASK_STARTED`

上传版本（顺序很重要）：

1. 读任务，校验归属（403）
2. 校验状态为 `DESIGNING` / `REVISION`（409）
3. 校验文件非空、扩展名在白名单
4. **先把文件落盘**（事务外）→ 得到 `yyyyMM/{uuid}.ext`
5. 开事务：取版本号 `MAX(version_no)+1` → `INSERT design_version` → `UPDATE material_task SET status='PENDING_CONFIRM'` → 写 `VERSION_UPLOADED`
6. 事务失败 → **删除已落盘文件**，避免孤儿文件

## 4. 页面反馈

| 结果 | 反馈 |
|---|---|
| 分派成功 | 任务行显示被分派人，按钮由"分派"变"改派"（仍限 PENDING） |
| 开始设计成功 | 状态标签"设计中" |
| 上传成功 | 版本时间线追加一条（版本号/文件名/大小/时间），状态变"待客户确认" |
| 403 | "设计人员只能处理分派给自己的任务"，页面不刷新 |
| 409 | 显示当前状态原因，刷新详情 |
| 400（文件类型） | 上传框下方提示，保留已选文件信息 |

## 5. 异常与边界

| 场景 | 预期 | 处理 |
|---|---|---|
| 分派给非设计人员/停用账号 | 400 | 服务层校验角色与状态 |
| 开始设计后再改派 | 409 | 仅 `PENDING` 可改派 |
| 未分派就上传 | 403 | 归属校验先行 |
| 上传超大文件 | 400 | `MaxUploadSizeExceededException` 统一处理，提示 20MB |
| 上传后事务回滚 | 无孤儿文件 | 落盘在事务外，失败时补偿删除 |
| 并发上传同一任务 | 版本号唯一索引兜底 | 冲突重试一次；仍冲突返回 409 |
| 路径穿越 `/api/files/../../etc/passwd` | 400 | `contains("..")` + `normalize()` + `startsWith` |
