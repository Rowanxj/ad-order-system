SELECT table_name, index_name FROM information_schema.statistics

exit;

**成功的标志**：最后那条 SELECT 打印出两行（`design_version / uk_task_version` 和

### 0.6 启动失败对照表

| 现象 | 原因 | 怎么修 |
|---|---|---|
| `Communications link failure` | MySQL 没启动 | `Get-Service MySQL80` 看 Status，不是 Running 就 `Start-Service MySQL80`（需要管理员） |
| `Access denied for user 'root'` | 密码不对 | 改 `backend/src/main/resources/application.yml` 里的默认值，或设环境变量 `DB_PASSWORD` |
| `Port 8080 was already in use` | 上次的后端没关 | `Get-Process java` 然后 `Stop-Process -Name java -Force` |
| 前端 `Port 5173 is in use` | 上次的 `npm run dev` 没关 | 关掉那个窗口，或按提示按 `Y` 换端口 |
| 登录提示「账号或密码错误」 | 库里没数据 | 你的库应该有 4 条 `sys_user`，没有就导入 `sql/data.sql` |
| 一直被踢回登录页 | 浏览器存了过期 token | F12 → Application → Local Storage → 删掉 `ad_token`，再登录 |

## 第 3 步：给「客户」和「我的任务」加分页

现在只有订单列表分页。加第二处时，**照抄订单列表的写法**，一共六处改动。

### 3.1 后端三处（以客户为例）

**① Mapper 接口**（`CustomerMapper.java`）：给 `selectList` 加两个参数，再加一个计数方法。

```java
List<Customer> selectList(@Param("keyword") String keyword,
                          @Param("offset") int offset,
                          @Param("size") int size);

int countList(@Param("keyword") String keyword);
```

**② Mapper XML**（`CustomerMapper.xml`）：末尾加 `LIMIT`，再复制一份同样的 where 做 count。

```xml
<select id="selectList" resultType="com.course.adorder.entity.Customer">
    SELECT id, name, contact_person, contact_phone, industry, remark, created_by, created_at, deleted
    FROM customer
    WHERE deleted = 0
    <if test="keyword != null and keyword != ''">
        AND (name LIKE CONCAT('%', #{keyword}, '%') OR contact_person LIKE CONCAT('%', #{keyword}, '%'))
    </if>
    ORDER BY id DESC
    LIMIT #{offset}, #{size}
</select>

<select id="countList" resultType="int">
    SELECT COUNT(*) FROM customer
    WHERE deleted = 0
    <if test="keyword != null and keyword != ''">
        AND (name LIKE CONCAT('%', #{keyword}, '%') OR contact_person LIKE CONCAT('%', #{keyword}, '%'))
    </if>
</select>
```

> 两个 where 必须一模一样，否则会出现「列表有数据、总数对不上」。

**③ Service + Controller**：Service 返回 `{list,total,page,size}`，
Controller 加 `@RequestParam(defaultValue="1") Integer page` 和 `size`。
直接照抄 `OrderService.list()` 的写法即可。

### 3.2 前端三处

1. `CustomerView.vue` 的 `load()` 改成读 `data.list` / `data.total`；
2. 表格底下加 `<el-pagination>`（照抄 `OrderListView.vue` 那段）；
3. 搜索、重置、改每页条数时都要 `page.value = 1`。

### 3.3 改完必须同步契约（**这一步最容易忘**）

分页改了接口返回结构，必须同时改：

| 文件 | 改什么 |

## 第 4 步：并发压测（可选，答辩加分）

目的：证明"两个人同时建单，订单号不会重复"。当前靠唯一索引兜底 + 重试，不压测等于没证据。

### 4.1 准备脚本

在项目根新建 `docs\concurrency-test.ps1`，内容：

```powershell
# 并发建单测试：同时发起 20 个请求，检查单号是否唯一
param([int]$Count = 20)
$base = 'http://localhost:8080/api'

$login = Invoke-RestMethod -Method Post -Uri "$base/auth/login" -ContentType 'application/json' `
    -Body '{"username":"sales","password":"123456"}'
$token = $login.data.token

$job = 1..$Count | ForEach-Object -Parallel {
    $body = @{
        customerId = 1
        title      = "并发测试-$_"
        deadline   = '2026-12-30'
        tasks      = @(@{ materialType = 'POSTER'; name = "并发海报-$_"; quantity = 1 })
    } | ConvertTo-Json -Depth 5
    try {
        $r = Invoke-RestMethod -Method Post -Uri "$using:base/orders" -ContentType 'application/json' `
            -Headers @{ Authorization = "Bearer $using:token" } -Body $body
        [pscustomobject]@{ code = $r.code; orderNo = $r.data.orderNo; msg = $r.message }
    } catch {
        [pscustomobject]@{ code = -1; orderNo = $null; msg = $_.Exception.Message }
    }
} -ThrottleLimit $Count

$ok = @($job | Where-Object { $_.code -eq 0 })
$bad = @($job | Where-Object { $_.code -ne 0 })
"成功 $($ok.Count) / $Count，失败 $($bad.Count)"
"不同单号数：$(@($ok.orderNo | Sort-Object -Unique).Count)"
if ($bad.Count) { $bad | Format-Table -AutoSize }
```

### 4.2 怎么跑、怎么看

```powershell
cd D:\Programming_learning\houduan\try\ad-order-system
powershell -ExecutionPolicy Bypass -File docs\concurrency-test.ps1 -Count 20
```

**通过标准**（三条同时满足）：

- `成功 20 / 20`；
- `不同单号数：20`（**这条最关键**，重复就说明取号有并发问题）；
- 失败列表为空，没有 `code=-1`（没有 500）。

### 4.3 如果不通过怎么办

- 出现 `订单编号生成冲突，请重试`：说明 3 次重试不够，把 `OrderService` 里
  `if (attempt >= 3)` 改成 `>= 5`；
- 出现重复单号：说明唯一索引没生效 —— 回到第 0.2 步检查 `uk_order_no` 是否存在；
- 出现 500：把后端窗口的报错贴出来。

### 4.4 记录

把结果写进 `docs/test-record.md`，例如：

```
并发建单：20 并发，成功 20，单号唯一 20/20（2026-11-05）
```
