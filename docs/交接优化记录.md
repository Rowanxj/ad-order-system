# 交接优化记录（2026-11-06）

> 本轮参考 `D:\desktop\项目文件.zip` 里的交接版本，对当前项目做了一次"取长补短"的优化。
> 原则：**不覆盖已有的任务工作台、通知和 80 条单测**，只采纳对答辩有实际价值、且不破坏现有契约的改动。
> 参考包里混有 `node_modules`、`target`、`.idea`、本机 `.env`，这些都没有复制进项目。

## 一、采纳了什么

### 1. 安全收口

| 原问题 | 处理 |
| --- | --- |
| 账号 JSON 可能带出密码摘要 | `User.password` 加 `@JsonIgnore`；`/users/designers` 改由 `UserService.designers()` 只返回 `{id,username,realName,status}`，且只列启用人员 |
| 设计稿下载没有数据归属校验 | `TaskService.resolve(viewer, path)` 先按 `file_path` 反查 `design_version`，设计人员只能下载本人任务的设计稿 |
| 数据库连不上只报"服务器内部错误" | `GlobalExceptionHandler` 对 `MyBatisSystemException` 返回"检查 MySQL 与 .env"的可读提示 |

### 2. 配置与构建

- `application.yml` 支持自动加载项目根目录或 `backend/` 下的 `.env`；
- `SERVER_PORT`、`JWT_EXPIRE_HOURS`、`UPLOAD_DIR`、`LOG_LEVEL` 真正可通过环境变量覆盖；
- Vite 把 `vue` / `element-plus` / `axios` 拆成独立 vendor chunk，业务代码更新不影响依赖缓存。

### 3. 业务规则

- 整体截止、物料截止不能早于今天；
- 物料截止不能晚于整单截止；
- 修改整单截止不能早于最晚物料截止；
- 确认前的截止日期调整也写 `ORDER_DEADLINE_CHANGED` / `TASK_DEADLINE_CHANGED`，异常管理才能标记「已延期」；
- 前端三个日期选择器同步禁用非法日期，后端 Service 仍是最终判定方。

### 4. 查询与页面

- 订单列表新增 `deadlineFrom` / `deadlineTo` / `overdue` / `extended`；
- `/api/tasks` 对客户经理开放，并新增 `extended`、返回 `orderDeadline`；
- 新增 `/dashboard` 工作台（角色指标、优先任务、逾期订单、快捷入口）；
- 新增 `/exceptions` 异常管理（逾期/待分派/待客户确认/已延期/可交付，左侧列表 + 右侧处理）；
- 登录后默认进工作台，导航增加"工作台/异常管理"。

## 三、明确没有采纳的

| 参考版本功能 | 原因 |
| --- | --- |
| 取消单项物料任务（任务新增 `CANCELLED` 状态） | 要改状态机契约、权限、验收和 DDL，答辩前不动 |
| `confirmed_version_no`（客户确认的是第几版） | 需要 `ALTER TABLE` + 页面/验收联动，留到下一轮 |
| 参考包的 `.idea`、`.env`、`node_modules`、`target` | 本机配置/构建产物，不应入库 |
